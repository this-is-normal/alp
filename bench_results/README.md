# bench_results

One record per benchmark run, in a shared format across all three layers we measure:

| layer | what it measures |
|---|---|
| `pcs` | one commitment scheme in isolation — field ops, hashes, proof bytes |
| `prover` | the whole Plonky3 multi-stark prover on a real AIR |
| `recursion` | a guest verifying a proof inside OpenVM — instructions, segments |
| `aggregation` | OpenVM `prove stark` / `prove evm` collapsing an app proof |

Each run is two files sharing a stem: a `.md` for the narrative and a `.json` for the numbers, so
trends can be diffed and plotted without re-reading prose. [`INDEX.md`](INDEX.md) is generated by
[`make_index.py`](make_index.py).

```
YYYY-MM-DD-<layer>-<target>-<variant>.md
YYYY-MM-DD-<layer>-<target>-<variant>.json
```

## Why the format is this strict

Every wrong turn in this project so far has been a **missing field**, not bad arithmetic:

| what went wrong | the field that prevents it |
|---|---|
| compared a 16-bit toy scalar against a 253-bit run and called it a regression | **target parameters** |
| read 1.09 s/segment on one box against ~2 s/segment on another as a slowdown | **hardware**, and a hardware-independent metric first |
| a guest revealed `0`; it looked like a logic bug and was a stale proof blob | **input artefacts** |
| a phase measured 3.4× its neighbour — an artifact of a compile-time ablation flag changing codegen | **build features** |
| predicted 36 M instructions from op-counts, delivered 5.4 M | **measured vs modelled** |
| a table constant silently cost 2.7× at one batch size | **full parameters, not just the headline** |
| a tool's default memory limit cost 1.2× | **the verbatim command** |

So: fill every field, or say `n/a` and why. A record that omits one is worse than no record,
because it will be trusted later.

## Rules that matter more than the template

**Hardware-independent numbers first.** Instructions, segments, cells, field-op counts, proof
bytes. Wall-clock second, and never without naming the box. Seconds have misled us across
machines; segment counts have not.

**Label every number measured or modelled.** Anything from a cost model is an *estimate*, and
op-count × microbench-cost is an **upper bound** — it has overshot by 6×, because a `black_box`ed
microbench loop forces spills that real code elides. Never quote a modelled figure as a result.

**State comparability explicitly.** `comparable-to` and `not-comparable-to` with a reason. A run is
not comparable to another with different parameters, a different box (for wall-clock), or a
different commit that touched the hot path.

**Record what got worse.** Negative results are results. Lazy twists, an allocation-free
`LimbIter`, and rate 1/16 on Quasar's inner code were all measured *worse* and reverted; without a
home they get re-attempted. Every record has a `Tried and rejected` section, even if empty.

## Provenance

Never type it. Run:

```bash
./bench_results/bench_record.sh            # local box
./bench_results/bench_record.sh vultr4     # measured on a remote box
./bench_results/bench_record.sh --json vultr4
```

It emits commit, branch, **uncommitted-file count**, CPU and cgroup quota, memory, GPU, CUDA,
rustc and `cargo-openvm`. The dirty flag matters: "commit abc123" is a lie if the tree had 25
uncommitted files, which has happened here.
